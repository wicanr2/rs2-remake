# 各關流程、背景、頭目、過場與素材用途

本文件整理每張圖的實際用途與各場景的顯示流程，作為 HD 重繪與 remake 規格的依據。資料表在 `workspace/extracted/sprite-usage.json`，由 `tools/export_sprite_usage.py` 從反組譯與映像重算。

位址一律是 IDA 線性位址十六進位。`dseg:X` 等於線性 `1CBC0h + X`。IDA 的名稱 `word_26888` 是線性位址，指令內的 `ds:9CC8h` 是同一個變數的 dseg 偏移。等級沿用 `AGENTS.md`：靜態已證實、強推論、假說、未知。沒有標等級的句子都是靜態已證實，也就是讀到機器碼，且 `export_sprite_usage.py` 的掃描值與它一致。尚未做動態驗證，影格速率未知，下文的「幀」是程式內的幀計數 `word_1CFE2`，每次畫一個頁面加 1。

## 1. 工具與輸出格式

```sh
docker run --rm --network none -u $(id -u):$(id -g) --memory 1g --cpus 2 --pids-limit 128 \
  --log-opt max-size=10m --log-opt max-file=3 \
  -v $PWD/workspace:/ws:ro -v $PWD/tools:/tools:ro -v $PWD/workspace/extracted:/out \
  python:3.12-slim timeout 300 python -I /tools/export_sprite_usage.py /ws /out/sprite-usage.json
```

工具的做法：

- 從 `start`（10000h）與一條自修改跳躍做指令層級的可達性分析，不看 IDA 的 proc 邊界。自修改跳躍是 `11619h` 的 `jmp short locret_1160D`，密碼檢查通過路徑會把它補成兩個 NOP（`12F0A`～`12F0D`），落點 `1161Bh` 是正式開始遊戲的程式碼，所以也列為起點。可達指令 14,463 條，總指令 18,784 條。
- 對每個 blit 呼叫點往回掃，取 `word_26880`（x）、`word_26882`（y）、`word_26888`（索引）、`word_2685C`（背景暫存區偏移）的最近一次立即值。
- 表驅動的用途直接讀映像：關卡時間表與實體樣板、敵彈與道具池樣板、玩家子彈樣板、特效腳本、第三關地圖。
- 人工判讀只放在 `OWNER_INFO` 等表，每項帶位址，執行時與掃描值對照，不符就中止並回非 0。

`sprite-usage.json` 的結構：

## 2. 繪圖介面

### 2.1 呼叫約定

| 變數 | 意思 |
|---|---|
| `word_26880` | x，單位是位元組（8 像素）。CGA／MGA 分支先乘 2 |
| `word_26882` | y，單位是像素列。`sub_19683` 會跳過 y<0 的列，`y>189`（`0BDh`）的列整列不畫，所以遊戲區只有 190 列，底下 10 列是介面用 |
| `word_26888` | 圖庫索引。`sub_18AA4` 取 `段:[索引×2]` 得到項偏移，項內第 1 字組是高，第 2 字組是每列位元組數。`sub_18AA4` 不檢查索引是否超過項數，超過時照樣讀圖庫段內的記憶體（第 4.6 節） |
| `word_2687E` | 每列位元組數。`sub_18AA4` 寫入，`sub_19683` 跳過 y<0 的列時用它推進來源指標（第 2.3 節） |
| `word_26870` | 圖庫段，由各 wrapper 依平面設定 |
| `word_26872` | 頁面位移。0 或 8000h（CGA 為 4000h） |
| `word_2685C` | 背景暫存區選擇，0 是暫存區 A，8000h 是暫存區 B |

頁面是 EGA 320x200 的兩頁，每頁每列 40 位元組，頁 0 在 `A000:0000`，頁 1 在 `A000:8000`。`sub_19A37` 顯示頁 0、改畫頁 1（`word_26872=8000h`），`sub_19A88` 相反。

### 2.2 背景暫存區

背景暫存區位在同一塊顯示記憶體內：每列 80 位元組（640 像素寬），列位址表在 `dseg:A19Ah`，起點 `1F40h`，所以暫存區 A 是 `1F40h`～`7FFFh`，暫存區 B 是 `9F40h`～`FFFFh`，每區最多約 300 列。這是為了做水平環繞捲動：同一張圖在 x=0 與 x=40 各畫一份。顯示頁本身用另一張列表 `dseg:A00Ah`（每列 40 位元組）。

`sub_19ADC` 與 `sub_19B40` 把平面資料以字組複製（`movsw`，所以寬度要是偶數位元組）寫進暫存區，不裁切不遮罩。之後每幀用 `sub_19BA4`、`sub_19D08` 等把暫存區的列以 GC 寫入模式 1（閂鎖複製）搬到顯示頁。

### 2.3 blit 變體

下表是 E 模式（EGA／VGA）的語意。每個 wrapper 先測 `byte_1CF74=='E'`，其他值走單色分支。

| wrapper | 圖庫與平面 | 底層 | 寫入方式與裁切 |
|---|---|---|---|
| `sub_18C0A` | MY 4 平面 | `loc_193E0` | 覆寫（MOV）。每列只寫 `[列起點, 列起點+27h]` 內的位元組，其餘裁掉；`y>189` 的列跳過 |
| `sub_18C6E` | MY 4 平面 | `loc_19534` | 資料取反後寫入，沿用目前的 GC 函式（`sub_18878` 設為 0，即覆寫），選單反白用 |
| `sub_18CE2`、`sub_18EB6` | MY 4 平面 | `loc_1938C` | 與目的做 OR。裁切同 `sub_18C0A`。兩者本體相同，各有呼叫者 |
| `sub_18D46`、`sub_18E30`、`sub_18E73` | MY 遮罩（`word_1CF5A`） | `loc_194DC` | GC 資料旋轉暫存器設 `0803h`（AND），先讀閂鎖再寫，遮罩位元 0 清掉目的。三者相同 |
| `sub_18D89` | MY 遮罩 | `loc_19534` | GC `1003h`（OR）寫入反相遮罩，剪影內全平面設 1，也就是填成色號 15。受傷閃白用 |

| 函式 | 動作 |
|---|---|
| `sub_19BA4` | 暫存區列複製到顯示頁，每列 40 位元組，來源起點 `1F40h + 列x80 + 欄 + word_26868 + word_2685C`，`y>189` 跳過。列是 `word_26866` 的低位元組（`19BC2h` 的 `mul bl`，`19DA8`、`1A09F`、`19D08` 同），超過 255 會環繞 |

| `sub_19C4F` | `sub_19BA4` 的垂直鏡射版（目的列遞減），第四關通道的上壁。列終止條件與 `sub_19BA4` 不同，見下表 |

| `sub_19F3B` | `sub_19DA8` 的垂直鏡射版（`sub_1A397`） |
| `sub_19E66` | 逐平面 OR，每列一個字組（16 像素）（`sub_1A453`） |
| `sub_19FF9` | 閂鎖複製，每列最多 2 位元組（16 像素）（`sub_1A41D`），覆寫 |
| `sub_1A09F` | AND 遮罩（GC `0803h`），整列 40 位元組（`sub_1A3C5`）。遮罩從 GC 索引 4 殘留的讀取平面讀（`1A3DAh`），實際是上一次 `sub_1882E` 選的平面 0 |
| `sub_1A1E6` | `sub_1A09F` 的垂直鏡射版（`sub_1A3F1`） |
| `sub_1A144` | AND，每列最多 2 位元組（`sub_1A48F`） |
| `sub_1A287` | 以 GC 寫入模式 2 填實色，`dx` 是色號，`cx` 是列數（`sub_1A4C9`），每列 40 位元組 |

搬到顯示頁的函式，每列規則不同（E 模式，內層函式的位址在括號內）。「列尾」是該顯示列的起點加 `27h`（`dx + 27h`），來源列距都是暫存區的 80 位元組，除非另註。

|---|---|---|---|---|
| `sub_19BA4` | 閂鎖複製 40 位元組（`rep movsb`） | 無 | 80 | 列號 > 189 |
| `sub_19C4F` | 同 `sub_19BA4`，目的每列減 `28h` | 無 | 80 | 列號每列減 1，列號 < 0（帶號比較）才停，沒有 189 上限 |
| `sub_19DA8`（`sub_1A369`） | 逐平面 OR 20 個字組（40 位元組） | 無 | 80 | 列號 > 189 |
| `sub_19F3B`（`sub_1A397`） | 同 `sub_19DA8`，目的每列減 `28h` | 無 | 80 | 列號每列加 1，> 189 才停；目的列往回走，沒有下界檢查 |
| `sub_1A09F`（`sub_1A3C5`） | AND 40 位元組（`lodsb`、`mov ah,[di]`、`stosb`） | 無 | 80 | 列號 > 189 |
| `sub_1A1E6`（`sub_1A3F1`） | 同 `sub_1A09F`，目的每列減 `28h` | 無 | 80 | 同 `sub_19F3B` |
| `sub_19E66`（`sub_1A453`） | 逐平面 OR 一個字組（`lodsw`、`or [di], ax`） | 以字組為單位：起點 `di` > 列尾就整個字組不寫；`di` 等於列尾時高位元組寫進下一列的第 0 欄 | 80（`si` 每列還原） | 列號 > 189 |
| `sub_19FF9`（`sub_1A41D`） | 閂鎖複製，`lodsb`、`stosb` 最多 2 位元組 | 以位元組為單位：`lodsb` 之後 `di` > 列尾就結束該列 | `lodsb` 次數加 `4Eh`：兩個位元組都讀到是 80，第一個位元組就被擋掉時是 79 | 列號 > 189 |
| `sub_1A144`（`sub_1A48F`） | AND 最多 2 位元組（`lodsb`、`mov ah,[di]`、`stosb`） | 同 `sub_19FF9` | 80（`si` 每列還原） | 列號 > 189 |

鏡射版的列號與目的位址方向相反：`sub_19F3B`、`sub_1A1E6` 的列號每列加 1，目的位址每列減 `28h`，終止條件只看列號，所以起點列 y 小於「列數減 1」時，目的位址越過頁起點，在同一個 64 KB 段內往回環繞，寫進暫存區的尾端（頁 0 環繞進暫存區 B，頁 8000h 進暫存區 A）。第二關火焰面頂端就是這種情況：`word_1D7C0` 在遞增前幀計數 c ≥ 640 時等於 673 − c，`sub_19F3B` 取 34 列，c = 641～673 越界；`sub_1A1E6` 取 22 列，c = 653～673 越界。靜態已證實，`wt_stage2` 涵蓋這段幀，顯示記憶體與原版相同。`sub_19C4F` 的列號每列減 1，到 0 就停，不會越過頁起點。

`sub_19683` 在 y < 0 時跳過上方的列，每跳一列把來源指標加 `word_2687E`，之後從第 0 列起算。`word_2687E` 是最近一次 `sub_18AA4` 載入圖庫項時存的每列位元組數（`sub_1A2D2` 例外，它先寫入 `50h`）。上表列距 80 的函式不載入圖庫項，跳過列時用的是這個殘值（暫存區的列距是 80，兩者可以不同）。`sub_19C4F` 在 y < 0 時還有一個後果：跳過之後列號是 0，`19C8Fh` 的 `cmp bx, 0` 與 `jl` 不成立，畫完一列才 `dec bx`，所以顯示列 0 被寫入一次，來源是起點加 |y| 乘 `word_2687E`；`cx` 被扣到不足時 `sub_19683` 設 `bx = 12Ch`，這一列同樣照畫，沒有被 189 的上限擋掉。靜態已證實。動態已證實：第四關通道上壁在 y = −10、−20 時，`wt_flow` 第 389 筆的 `ds:9CBEh`（即 `word_2687E`）是 5。`wt_flow` 第 389 筆、`wt_stage4` 第 14 筆、`wt_fz4-sweep-3` 第 14 筆、`wt_fz4-seeker-2` 第 18 筆的 `sub_19C4F` 命令，結果取決於這個殘值（影響平面 3 頁 1 列 0 的一個位元組）；繪製命令帶著 `ds:9CBEh` 時，四筆都與原版逐位元組相同。

單色分支：CGA（`C`）與 MGA／Hercules（`H`）把 x 乘 2，改用 `sub_19892`（覆寫）、`sub_1979F`（OR）、`sub_1974B`（AND）、`sub_197EE`（反相 OR）、`sub_19840`（反相覆寫）等字組版本，圖庫換成 `.BDB`、`.BDH`、`.GOB`，寬度是彩色版的 2 倍。單色路徑 `y` 上限用 `0BEh`（190），比彩色多 1 列。CGA 另外有 `sub_198E1`、`sub_19925` 的填色版本，填 `dx==0Bh` 時改成 `0AAAAh` 點陣。這些分支沒有彩色版缺少的畫面，細節見第 10 節。

### 2.4 遮罩與平面的配對規則

遮罩與平面用同一個索引（同一個 `word_26888`），由 wrapper 換段。常見畫法有三種：

| 畫法 | 呼叫序列 | 遮罩 y 與平面 y |
|---|---|---|
| 主角機體、道具圓球（`M` 池）| 遮罩 AND，`inc word_26882`，平面 OR | 平面比遮罩低 1 列，遮罩多出的 1 圈黑邊在上與下 |
| 實體（`sub_164F3`）| `sub_18F1A`，`inc`，`sub_18F5D` | 同上，平面低 1 列 |
| 子彈、特效、砲座、ACT 字樣、敵彈（`SHT` 池）| 遮罩 AND，平面 OR | 同一 y |

實體影格索引的算法（`sub_15F4C`、`sub_16145`）：樣板第 1 字組（`word_1F178`）指向 9 字組的影格表，樣板第 20 字組（`word_1F19E`）指向 9 字組的動畫上限表或為 0。每幀讀移動腳本一個位元組 `d`（方向 0～8）：

移動腳本位元組（`sub_15E68`、`sub_15ECD`、`sub_15FD9`）：`1～8` 八方向（1 北、3 東、5 南、7 西，偶數是斜向），`0Bh` 發 B 型彈，`0Dh` 地形判定，`0Fh` 實體消失（走到終點），`F0 xx xx` 跳到 `xxxx` 續讀，`E0 xx xx` 把實體整份換成位址 `xxxx` 的另一份樣板（變形、放大）。換樣板鏈的所有索引屬同一組，工具已合併。

## 10. 單色模式差異

可達碼中所有 `byte_1CF74` 與 `byte ptr ds:3B4h` 的判斷集中在三處：wrapper 與暫存區搬移函式（第 2 節）、調色盤設定函式（非 E 模式直接返回）、各圖庫載入函式（換檔名與配置大小）。遊戲邏輯函式（各關主循環、實體、玩家、頭目）沒有任何模式分支，單色版與彩色版走同一條流程。資料有一處不同：第三關的地圖陣列也是地形碰撞格，彩色讀 `SHT.SCN`，單色讀 `SHT.SCR`，兩者有 514 格的零與非零不同，所以第三關的碰撞隨模式改變。完整盤點見 [14](14-display-modes.md)。

| 項目 | 差異 |
|---|---|
| 圖庫 | 單色版用 `.BDB`、`.BDH`、`.GOB`，圖庫項數與彩色版相同，只有 `MAP`：`MAP.BDB` 1,007 塊（16x10），搭配 `SHT.SCR`；`MAP.GO` 1,019 塊（8x10），搭配 `SHT.SCN` |
| 寬度 | 單色圖的位元組寬度是彩色的 2 倍，繪製時 x 乘 2 |
| 遮罩 | `MYB.BDT` 68 項，`SHTn.BDH` 與彩色遮罩項數相同；`SHT4.GOT` 只有彩色模式讀 |
| 填色 | CGA 的血條格與 `sub_1A287` 填色 `dx==1` 或 `0Bh` 時改成 `0AAAAh` 點陣 |
| 頁面切換 | CGA 用 BIOS `int 10h AH=5` 與 4000h 位移，MGA 用 3B8h 埠，E 模式用 CRTC 起始位址 |
| 單色專屬畫面 | 沒有發現。`sub_1117F` 的 `H` 分支只是把 `B000` 段的第 0 組 8KB 複製到第 2000h 位移（Hercules 掃描列組複製），其後 `111A9`、`111CA` 兩段是不可達的偵錯傾印（各圖庫段位址的十六進位列表） |

`sub_18B32`（MAP 圖塊寫 `7Fh` 位元組的格線標記）與 `sub_1852B` 不可達，是開發用的格線顯示，不屬於玩家畫面。
