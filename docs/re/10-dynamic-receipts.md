### 三種執行配置

| 配置 | 做法 | 對應 |
|---|---|---|
| A | 先跑 `ASMDRV.EXE`，用 dosgolem 的監督佇列與 `int 21h AH=31h` 讓它常駐，再接 `S.EXE`；`-adlib` 讓 OPL2 偵測成功 | `RS2.BAT` 的順序，AdLib 存在。路徑 A，不需要改 dosgolem |

### 位址與時間

- 腳本與日誌的遊戲位址一律是 IDA 線性位址（映像基底 `10000h`）。驅動在遊戲 INT 8 或 INT 9 向量指到 `CS:A7B5`／`CS:A83D` 時，取該 `CS` 的線性位址為基底，執行期位址 = 基底 + (IDA − `10000h`)。A 配置基底為 `05110h`，B 配置為 `01100h`。
- 虛擬秒 = 送出的 IRQ0 數 ÷ PIT 通道 0 當下頻率，累加。頻率來自程式寫進 8254 的除數，不是 18.2 Hz 的推算。`StepsPerSecondNow()`（`IRQ0Every × PITHz`）在三種配置都是每秒約 11.58 M 道指令（量到 11,580,826～11,580,906）。計時器沒有釘死（不用 `-tick`），兩個時間基準一致。
- IF 關著時合併掉的 IRQ0 不補。三種配置的量測窗口以 15 秒計，誤差在 ±1 個 tick。
- 輸入走 IRQ1（埠 60h）。遊戲本體沒有任何 `int 16h` 呼叫，只有破解組 intro 讀 BIOS 緩衝區。

### 破解組 intro

- 起始就送鍵的 `cmd/run -keys v` 在 6,000 萬步後仍停在 `0A79:08BD`。intro 在 `1A2BA` 先 `int 16h AH=0` 讀走按鍵，再檢查 `byte_19D67`（`sub_19D44` 每個垂直回掃加 1，數到 `0FAh` 才放行）。回掃計數不足時鍵被讀走丟掉。等級：現象動態已證實，機制靜態已證實。
- 第 45,000,000 步以 BIOS 鍵送 `v` 即可通過。之後 intro 跳進內層 stub，遊戲自己裝 INT 9（`1A83Dh`）與 INT 8（`1A7B5h`）（`vec` 事件，步 45,587,882～45,587,907）。

### 文字選單

- V、E、C、H 設定 `byte_1CF74／1CF75`：V = `E`,`N`；E = `E`,`Y`；C = `C`,`N`；H = `H`,`N`（`mode_v/e/c/h`）。E 模式才是純 EGA 調色盤，與 `CONTEXT.md` 的術語一致。
- 按 V 後遊戲立刻開 `A.MIX`（步 70,000,272）。

### 密碼畫面

- 三列各有 `RED WHITE YELLOW BLACK BLUE`。左（4Bh）右（4Dh）選色，Enter（1Ch）或空白（39h）確認，一列確認後進下一列（`sub_1097D`）。
- 三列全選預設色，或各選不同顏色（`pw_variants`：第一列右右、第二列左、第三列右右右右），都放行，`word_1D3B0` = 0。這份拷貝任意作答都通過。表的內容不記錄。

### 從標題進遊戲

- 開場（`BEG1`）期間任何鍵都進正式遊戲：按鍵當下開 `J1.GO`，PIT 回到 65536（音樂停止），J1 畫面等第二次按鍵，之後開 `BH1.GO`、`SHT1.GO`、`DM1.LCK`、`B.MIX`，第一關開始。

- 不按鍵時的循環（`demo`）：開場與標題（`A.MIX` 載入起約 13 秒）→ `DM1` 展示（22.2～106.6 秒）→ `DM2` 展示（106.6～146.8 秒，幀 0～366）→ 開場。`DM1` 到 `DM2` 之間沒有重新載入 `A.MIX`，`DM2` 結束時才重新開場。

  - LEVEL 預設 1（NORMAL）時 `word_1E6B4/1E6B2` = 2/0；右移一格到 2（HARD）時為 2/1。與 `03` 的表一致。
  - CTRL 選 2（2 PLAYERS）後開始遊戲，`byte_1CFDD` = `11h`，兩個玩家血量 `FFh`（`m_3_stage1_two_players`）。選單前 `byte_1CFDD` = 0，`sub_127A5` 在 `sub_12438`（開始遊戲）時才寫入。第二艘機體在前 4 秒的畫面沒有看到，未確認其位置。

### dosgolem 的缺口

`S.EXE` 的字串表有 `MY.GO ` 這樣尾端帶空白的名字。第 3 個副檔名位置留給 `sub_1C738` 改寫成 `B`，彩色模式不改寫。DOS 的路徑正規化會略過名字裡的空白（DOSBox-X `DOS_MakeName`），原版 dosgolem 找不到檔，遊戲在 `sub_1C82C` 每 16 步重試一次開檔，畫面停在密碼之後。patch 0001 補上，`TestResolveIgnoresSpaces` 在沒有 patch 時失敗、有 patch 時通過。

## 3. 影格速率與時基

收據：`fps` 腳本，A、B、C 三種配置，輸出 `fpsA`、`fpsB`、`fpsC`；另 `stage1`～`stage4` 各有 12 秒窗口（`s*_fps`）。`measure` 以虛擬秒為窗口，遊戲 tick 以 `word_273B9` 的 `+1` 計數（每次 INT 8 處理常式 `inc word_273B9`，歸零不算），幀以 `word_1CFE2` 計數，等待迴圈以 `sub_11097`（`11097h`、`1109Bh`）的執行步數計數。

| 配置 | 階段 | PIT 通道 0 | 遊戲 tick | 幀 |
|---|---|---|---|---|
| A | 標題與開場（5.0 秒） | 400.128 Hz（除數 2982） | 18.1967 Hz（91 個） | |
| A | J1 過場 | 18.2065 Hz（65536） | 18.2065 Hz | |
| A | 第一關（15 秒 ×2） | 480.154 Hz（除數 2485） | 18.1982 Hz（273 個） | 137、136 幀，9.13、9.07 幀／秒，每幀 1.993、2.007 tick |
| B | 全程 | 18.2065 Hz，從未改寫 | 18.2065 Hz | 第一關 137 幀／15.0496 秒 = 9.1033 幀／秒，每幀 2.0000 tick |
| C | 全程 | 同 B | 同 B | 同 B（步數逐位元相同：655,332,551） |
| A | 第一至四關（12 秒） | 480.154 Hz | 18.2495 Hz（219 個） | 109～110 幀，9.08～9.17 幀／秒 |

結論：

- 遊戲的時間基準是 `ASMDRV` 轉發後的 18.2065 Hz。`word_273B9` 每次 +1 的頻率在三種配置相同，與 PIT 頻率無關。`sub_11097` 等 2 個 tick，一幀 9.10 幀／秒。程式內所有關卡的幀末等待都是 `cx = 2`（`10F98h`、`13336h`、`13B59h`、`13EEEh` 前的 `mov cx, 2`）。顯示頁翻轉與幀計數一對一（A 的 137 次／15 秒）。
- `_CLK_INSTALL`（`ASMDRV` `11050h`）在 INT 60h `AX=2`（載入）時被呼叫：先 `out 43h, 36h` 把通道 0 設成除數 0（65536），用 `AH=35h` 存舊 INT 8，再以 `AH=25h` 掛 `0110:10B8`。`_CLK_UNINSTALL`（`11096h`）在 `AX=3`（停止）時還原。除數由 `1100Fh` 寫入。
- `ASMDRV` 的 INT 8 處理常式（`110B8h`）每個 IRQ0 把除數加進 16 位元累加器 `cs:1000h`，進位才用 `pushf` 加 `call far` 轉發舊處理常式（遊戲在 `A7B5h` 的那一個）。平均轉發頻率 1,193,181.8 ÷ 65,536 = 18.2065 Hz，單窗口有 ±1 tick 的抖動。轉發的是遊戲自己的處理常式，所以遊戲 tick 不跟著加快。這解釋了 A 配置 PIT 在 400～480 Hz，遊戲仍是 9.1 幀／秒。
- PIT 頻率與音樂有關：`A.MIX` 啟動時 2982（400.128 Hz），`B.MIX` 啟動時 2485（480.154 Hz）。兩個值是 4 × 速度欄（`A.MIX` 100、`B.MIX` 120）換成除數後取整數（1,193,182 ÷ 400 = 2982.9，÷ 480 = 2485.8）。等級：強推論（兩個資料點）。
- 每幀忙碌步數：第一關約 10.1 萬～13.4 萬道指令，第二關 13.2 萬，第三關 5.8 萬，第四關 4.7 萬。一幀的時間 126 萬步，等待迴圈佔 89.5%～96.3%。步數是 dosgolem 的指令數，不是週期。
- 同一窗口內 A 比 B 多出 OPL 寫入（第一關 1,520～1,699 次／15 秒），喇叭通道 42h 的寫入數相同（11,844）。

## 5. 熱鍵與秘技

按鍵狀態表在 `線性 2748Bh + 掃描碼`，按下為 1，放開為 2。主迴圈每幀（約 110 ms）輪詢一次，狀態必須在輪詢時為 1。

| 按鍵 | 收據 | 結果 |
|---|---|---|
| Ctrl+C | `stage1`～`stage4`、`ending` | 立即結束該關，開下一個 `Jn.GO`，PIT 回到 65536。第四關按則進片尾（開 `SHT5.GO`，調色盤 `ending_a`） |
| Ctrl+Q | `hot_quit`（`hot-quit.txt`） | 立即結束，exit code 76（`4Ch`，`10077h` 的 `mov ax, 4C4Ch`）。片尾中單按 Q（掃描碼 10h，無 Ctrl）也結束，exit code 同為 76 |
| Ctrl+R | `hot_keys`、`ending` | 第一關進行中回標題（重新開 `A.MIX`、`BEG1.BD1`～`BD4`）。片尾動畫循環中仍留在片尾（`en_6_after_ctrlr`，`ending_b`），沒有離開；靜態看是重設幀計數重播循環（`141D9h`），重播的幀計數沒有驗 |
| Ctrl+W | `hot_capture`、`hot_misc` | 寫 `PIC.DA1`～`DA4`，各 8000 位元組。內容與 EGA 平面 3、2、1、0 的頁 0（偏移 0）逐位元組相同。按住期間每幀擷取一次（0.4 秒得 2 次，8 次寫檔）；W 只按 4 ms 會被漏掉。擷取的是頁 0，不是目前顯示頁 |
| Alt+W | `hot_misc`、`hot_capture` | 沒有擷取。Alt 實體按住時 `byte_274C3` = 0（Ctrl 時 `byte_274A8` = 1）：秘技的 `sub_1A8F4` 在 INT 9 內一看到 `byte_274C3 == 1` 就清成 0。因此 `10DF8h` 的 Alt+W 路徑不可達 |
| Ctrl+D | `hot_ctrld`、`hot_ctrld_noasm` | 配置 A：呼叫 `byte_10AD4`，INT 60h `AX=0`、`2`、`4`；之後遊戲 tick 停止，幀計數停在 11，`word_273B9` 停在 0（`hd_*`）。配置 B：`byte_10AD4` 在沒有 AdLib 時被改成 `retn`，無影響，幀繼續（10 → 23 → 51） |
| S | `hot_misc`、`sound_toggle` | 切換 `byte_2684E`（0 與 1 輪流）。旗標為 1 的 5.3 秒窗口，OPL 寫入 0 次、喇叭閘極（埠 61h）寫入 0 次；旗標為 0 的窗口各 481～547、2,384～2,712 次。旗標 1 是靜音 |
| 任意鍵（展示模式中） | `cold`、`demo` | 離開展示，回開場（`sub_10D99` 的 `byte_1CFDC == 'Y'` 分支） |

### Ctrl+D 凍結的原因

`byte_10AD4`（音樂啟動）依序呼叫 `AX=0`、`2`、`4`，沒有先停止。`AX=2` 的 `_CLK_INSTALL` 讀目前的 INT 8 向量，此時已經是 `ASMDRV` 自己的 `0110:10B8`，存成「舊處理常式」。之後累加器進位時轉發給自己，遊戲的 INT 8 處理常式（`A7B5h`）再也沒被呼叫，`sub_11097` 永遠等不到 tick。正常的停止序列是 `AX=5`、`3`、`0`（`10B12h`）。這是原版程式碼的行為，等級動態已證實，原因靜態已證實（`ASMDRV` `11050h`、`11096h`、`100D5h`）。

### 開發者秘技

收據：`hot_cheat`（變數取值見 `events.tsv` 的 `peek` 行）。`sub_1A8F4` 在每次 INT 9 檢查。

## 7. ASMDRV

- 路徑 A：dosgolem 的監督佇列加 `int 21h AH=31h` 可以直接串接，`S.EXE` 的 `AH=4Bh` 不需要。`ASMDRV` 用 `AH=35h`／`25h` 掛 `INT 60h`（`0110:0038`，步 54,408），`AH=31h` 保留 `DX=400h` 段後結束，佇列接著載 `S.EXE`（步 211,976）。程式不需修改，dosgolem 不需修改。
- 路徑 B：不載 `ASMDRV`。`INT 60h` 回傳暫存器不變，`sub_10A90` 判定 `AX` 不等於 1，把 `10AD4h`、`10B12h` 的首位元組改成 `C3`，音樂函式變成 `retn`。配置 B 與 C 都是這條結果。
- `INT 60h` 呼叫：偵測 `AX=0`（回 1 表示 AdLib）、`AX=2`（載入音色，ES:DI）、`AX=4`（開始）；停止序列 `AX=5`、`3`、`0`。`ASMDRV` 的 INT 8 處理常式與 PIT 的作法見第 3 節。
