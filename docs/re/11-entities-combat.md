# 實體與戰鬥邏輯

範圍：敵方實體、移動腳本、生成、碰撞、玩家武器、敵方子彈、特效、難度、亂數、玩家與分數。本文件是 DRAFT 規格的證據層，不是 READY 規格。

來源與工具：`workspace/unpacked/S.unpacked.bin`（SHA-256 `8475b41b…de72`）。可機械匯出的資料由 `tools/export_entities.py` 讀映像產生 `workspace/extracted/entities.json`，工具要求 46 個函式簽章各在映像中恰好出現一次，派發表與機器碼立即值一致，否則中止。

位址寫法：程式碼用線性位址（例 `15E68h`）。資料用 `dseg:XXXXh`（線性 = `1CBC0h` + 位移，解包映像位移 = `0CBC0h` + 位移）。IDA 名稱 `word_1F190` 是線性位址 `1F190h` = `dseg:25D0h`，只作導覽。

等級：靜態已證實（S）、強推論（I）、假說（H）、未知（U）。未標示的規則為 S。尚無動態驗證，所有 S 都是機器碼與資料的讀取結果。

### 2.3 碰撞形狀

`w14` 指向 `u16 寬, u16 高, 寬 × 高 位元組`，列優先，左上角對齊 (x, y)。格值 0 無作用，1 實心，`FEh` 為裝甲（只有 `dseg:8441h` 使用）。匯出 171 個樣板（時間表直接引用 147 個，另 24 個只由 E0 變身到達），形狀尺寸 1×1 到 59×19，格值只出現 0、1、FEh（共 90 個 FEh）。形狀最寬 59，生成於 x = 40 時大半在螢幕外。寫入時逐格裁掉欄 < 0 或 > 39（`16262h` 起的 `di` 範圍檢查）與列 ≥ 19（`16251h`），形狀列在螢幕上方時整列跳過並推進讀取指標（`16290h`）。

### 3.3 追蹤路徑（`word_1F186` = `A`，`15E9Ah`）

### 5.2 玩家子彈 vs G1（`16B49h`）

形狀由 `[w14]` 的寬高決定，左上角在 (w9, w10)，逐格掃描。可測範圍：欄 1 至 38（`16B7Ah`：`di > 列基底`；`16B76h`：`di < 列基底 + 27h`），列 0 至 18（`16B6Ah`：`di < 1E2Ah`）。每格：

- 其他：記錄為 `byte_1F1C0h`（後掃到的覆蓋前面），子彈消失。

### 5.3 雷射（子彈型別 `L`、`l`）

`16A4Eh`（朝右）、`16ACAh`（朝左）。從子彈欄往行進方向逐格掃：G4 同列上一列（`dec bx` 後 `16A2Ch`）有非 0 字組即停；G1 的格值 0、FFh 繼續，其他格記錄為命中並停；掃到欄 39（朝右）或列基底（朝左）也停。畫一道由子彈位置起、長度為掃描格數的光束（圖 4 或 19h，頁奇偶交替），子彈當幀移除。命中時依 5.2 的 `16946h` 加 1 傷害，特效 `>` 或 `<` 在光束末端。雷射路徑沒有 FEh 檢查，記錄值為 FEh 時 `1694Dh` 的 `dec al` 得 FDh，以索引 FDh 讀到 `dseg:248Eh`（實體槽 9 的 w21）當實體指標，實測全為 0，於是把傷害字組寫到 `dseg:0020h`。砲座接觸路徑 `14B95h` 同樣沒有 FEh 檢查，之後走 `sub_14C18` 的同型運算。`dseg:0020h` 是 `byte_1CBE0`，啟動時文字畫面的色彩屬性（`sub_10633`、`sub_10643`），關卡內不再讀取，裝甲格也確實不受傷，所以沒有玩家可見的影響（[10](10-dynamic-receipts.md) 第 10.2 節）。指向已釋放槽的格值走同一路徑，也寫 `dseg:0020h`。

### 5.4 道具判定（`14CD4h`）

敵方子彈格值 = 形狀格值 + 子彈槽號。道具形狀的格值：`L` 81h、`B` 41h、`K` C1h、`S` 21h（`dseg:3F4Ah`、`3F54h`、`3F5Eh`、`3F68h`，皆 2×3）。玩家本體讀到非 0 格先刪除該子彈（槽號 = 格值 and 0Fh 減 1，`14D54h`），再以 `格值 and F0h` 判定：80h、40h、C0h、20h 為道具，記錄 `byte_1DAA8h`；其餘設 `byte_1DAC0h` = `Y`。槽號 15 以上時（同時在飛的敵方子彈超過 15 顆），格值 and 0Fh 回繞：槽 15 得 FFh，把 0 寫到 `dseg:34B1h`（槽 15 記錄的 y）；槽 16 至 19 得槽 0 至 3（刪錯子彈，擊中的那顆留在池裡）。第三、四關頭目戰可實際觸發，收據見 [10](10-dynamic-receipts.md) 第 10.1 節。道具格值 81h 加槽號 15 以上會進位到高四位元，道具判定落空而當成傷害，這一支靜態成立，自然流程沒有觀察到。

### 5.5 命中結算

玩家端：`sub_14501`（`14501h`）每幀讀 `byte_1DAC0h`。若為 `Y`：`word_1CFDE` 右移一位（作弊旗標 `word_273A5` = `Y` 時不移），重畫血條，`byte_1DAC1h` = 6；若血量為 0 進死亡（9.5）。`byte_1DAC1h` > 0 的幀，`sub_14704` 走 `14748h`：遞減、只畫遮罩、跳過所有碰撞檢查，所以命中後 6 幀無敵。

實體端：`sub_15F8D`（`15F8Dh`）每幀先重設 `word_1E6B6h`、`word_1EDAAh` 為 `N`，若 w16 的高位元組為 1：w16 = 低位元組；若 w16 ≤ w0 + `word_1E6B2h`（難度修正）則 `word_1E6B6h` = `Y`（本幀閃爍）；否則 `word_1EDAAh` = `Y`，以 (w9, w10) 與 w17 呼叫 `sub_17A3A` 播爆炸。w16 低位元組在整個生命週期累計，不會歸零。所以：

```text

一般子彈擊中次數 = hp + 修正 + 1；型別 S、A 子彈每次 3 點
```

傷害與結算差一幀：子彈或砲座在第 t 幀寫 w16（步驟 9、10），實體在第 t+1 幀步驟 3 才結算。實體死亡後 `sub_15DBE`（`15DBEh`）依序：w7 = `E` 設過關旗標；清槽指標；若 kind 為 `K` 以 w1 的 (圖, x, y) 蓋背景；否則若 w19 為 `P` 以 w7 字母呼叫 `sub_16D3B`，位置 (w9, w10+2)。

### 7.3 瞄準（`sub_172DE`、`sub_16F9F`）

目標選擇（`172DEh`）：只有一位玩家存活時取該玩家；兩位都在時取水平欄距較小者。平手規則：發射點在兩玩家之間時取左邊的那位（`17335h`、`1734Bh`）；兩位同欄時，發射點在其右（`17301h`）取玩家 2、在其左（`17324h`）取玩家 1。目標座標取玩家的 (欄, 列)。

```text
若 0 <= y-3 <= 20 且 y-3 > ty:        # 目標在上方
    x-10 > tx → 8；x+10 < tx → 2；否則 1
否則若 y+3 < ty:                      # 目標在下方

否則:                                  # 同列（±3）
```

程式內沒有分數系統：沒有 SCORE 之類的字串（解包映像字串表），沒有累加分數的記憶體，介面只有兩條血條。`sub_16C7D`（`16C7Dh`）是一組命中計數器：`word_1F1B8h`（玩家 1）、`word_1F1BAh`（玩家 2）加 1 後以 `sub_1890D` 畫五位數字在 (23h, BEh) 與 (0, BEh)。但它的觸發條件是子彈 w7 為 31h 或 32h（`16C80h`、`16C87h`），而 w7 取自 `word_1F1BCh`（`165C8h`），所有寫入端只寫 0、`F`、`L`、`B`、`K`、`S`（`1460Ch`、`14661h`、`1488Bh`、`148AAh`、`1513Ah`、`1518Fh`、`153B9h`、`153D8h` 與玩家 2 的 `word_1DB0Bh`），樣板 w7 皆為 0。結論：計數器碼存在，但目前資料下不可達（I）。
