# 啟動鏈、加殼與破解層

工具：`tools/unpack_exe.py`，IDA 9.4 `ida-pro-9.4-idapython:py312-v1`。下列行為已用 dosgolem 走通，收據見 [10-dynamic-receipts.md](10-dynamic-receipts.md)：intro 要累積 250 個垂直回掃才認 `int 16h` 的鍵，密碼畫面任意作答都放行，`byte_273AD` 全程是 `'Y'`。

## 批次檔

`RS2.BAT` 依序執行：

```text
SEN          破解 TSR（第三方）
ASMDRV       AdLib 音樂驅動 TSR，掛 INT 60h
JGAME RS2    設定 JOYMOUSE 介面卡，讀 JOYMOUSE.CFG 與 RS2.JOY
S            遊戲主程式
SEN          再跑一次，移除破解 TSR
```

## S.EXE 的三層

| 層 | 內容 | 位置 | 判定依據 |
|---|---|---|---|
| 外殼 | LZEXE 0.91 演算法，檔頭 `1Ch` 的簽章被改成四個空白 | 檔案本身 | 解壓後大小 55,464，stub 特徵相符 |
| 破解組 intro | 包裝碼入口 `0969:0100`，映像位移 `9790h`，用 ROM 字型顯示捲動字串 | 第一層解開後 | 字串明寫 Future Brain Inc. |
| 內層 | 第二個 LZEXE stub 在 `0942:000E`，簽章同樣被抹除 | 第一層映像 | 解壓後 95,908 位元組，436 筆重定位，字串正常 |

解包結果雜湊：

| 產物 | SHA-256 |
|---|---|
| `S.layer1.bin` | `fc9311b93a5e785e24bdc02f43ed575ef23849046f4adcc756f961c529626fb6` |
| `S.unpacked.bin` | `8475b41b45507ab10f0430238e5d20a11563b7d1b202997680f73a7cab34de72` |
| `S.unpacked.exe` | `17d824cb3a00b82e989632f24ea8eccaf22ee67527eac57942e3b2f6aae391c3` |

intro 結束時跳到 `0942:000E`，目標值藏在 `dword_19794`。表面值是 `0942:040C`，`sub_19E70` 會 `xor 402h` 改成 `000E`。這一段的等級是強推論，因為 `sub_19E70` 的呼叫次數沒有逐一追完，但結果落在 stub 入口。

`ASMDRV.EXE` 是 LZEXE 0.90（簽章 `LZ09`）。解包後含 Borland 除錯符號，物件檔名有 `ASMDRV.OBJ`、`ADLIB.OBJ`、`OUTCHIP.OBJ`、`TIMER2.OBJ`、`EMLIB.OBJ`。`SEN.EXE` 外殼也是 LZEXE，簽章被改成 `Lss `。`JGAME.EXE` 未加殼，字串顯示以 Turbo C 1988 編譯。

## 靜態破解補丁

`SEN.PAS` 掃描記憶體，把下列 7 位元組換掉：

| | 位元組 | 指令 |
|---|---|---|
| 要找的 | `83 3E F0 07 00 75 0B` | `cmp word ptr ds:7F0h, 0` / `jnz +0Bh` |
| 換成 | `C7 06 F0 07 00 00 90` | `mov word ptr ds:7F0h, 0` / `nop` |

解包映像掃描結果：要找的樣式 0 處，換成的樣式 1 處，位於 `12F03h`。補丁之後的 `12F0Ah + 0Bh = 12F15h` 正好是第二次機會的分支起點。

結論：這份 `S.EXE` 已把 `SEN` 的補丁固化進去，所以 `RS2.BAT` 裡的 `SEN` 找不到目標，依 `SEN.PAS` 邏輯只會響一聲。補丁位元組與放行行為已證實，「原本是什麼」要有未破解的原版才能直接證實。

`ds:7F0h` 是 `word_1D3B0`，記錄答錯次數。

## 密碼畫面

| 位址 | 行為 | 等級 |
|---|---|---|
| `start` → `sub_10671` | 文字選單之後進入密碼函式，答錯時 `10979h` 跳回重來 | 靜態已證實 |
| `1096Bh` | 印 `dseg:1F3h` 的 PASSWORD 畫面，呼叫 `12DD0h` | 靜態已證實 |
| `12D91h` | 以 `word_1D3AE × 1Ah + word_1D3A8 - 1` 查 `dseg:8BDh` 的表，算出期望值 | 靜態已證實 |
| `12E1Dh` | 把 `loc_11619` 寫成 `EB F2`。磁碟上的初值也是 `EB F2`，要通過檢查才會被還原 | 靜態已證實 |
| `12E2Fh` 起 | 三組 `cmp ax, imm16`，立即數在執行時由 `12DE8h` 這類指令改寫 | 強推論，中段被 IDA 當成資料，未整段重建 |
| `12F03h` | 補丁點，答錯次數無條件歸零 | 靜態已證實 |
| `12F0Ah` | 把 `loc_11619` 還原成 `90 90`，之後才能開始遊戲 | 靜態已證實 |
| `12F15h` | 第一次答錯設 `byte_1D3A3` 並回 `dx='N'` 重來。第二次回 `dx='Y'` 放行，但失敗狀態留著 | 靜態已證實，這份拷貝走不到 |
| `1161Bh` | 開始遊戲前檢查 `word_1D3B0`，非 0 就返回。配合 `loc_11619` 的 `EB F2`，標題畫面會顯示，但無法開始遊戲 | 靜態已證實，組合行為未實跑 |
| `138F9h` | 第二關配置記憶體時再檢查 `word_1D3B0`，非 0 就跳回 `sub_13205` 開頭 | 靜態已證實 |

`PASSWORD` 字串下方有 `RED WHITE YELLOW BLACK BLUE`，密碼表每列 26 欄。這些線索指向查手冊顏色代碼的防拷，等級為強推論，手冊內容未知。依專案規則，表的內容不寫進文件。

remake 不需要重現這個檢查。是否保留成可選的懷舊畫面，等進入規格階段再決定。

## 計時中斷裡的列位址干擾碼

`1A7DAh` 在 `byte_273AD` 不等於 `'Y'` 時，每個 tick 改動 `dseg:A00Ah`～`A262h` 的掃描線位址表。這張表決定繪圖落點，改動後畫面會逐漸錯亂。

`byte_273AD` 的初值是 `59h`（`'Y'`），全檔沒有直接寫入，實跑全程維持 `'Y'`，這段碼沒有執行過。用途推測是反竄改，屬於假說。

## 其他執行期行為

| 位址 | 行為 |
|---|---|
| `start` | `SETBLOCK`、把堆疊移到 `9800:3000`、設定文字模式、掛 INT 9（`sub_1A720`）與 INT 8（`sub_1A789`） |

| `sub_12F27` | 把低位記憶體每個字組的最低位 XOR 進 `word_1D3A8`，再讀系統時間。推定為密碼題目的亂數來源 |
