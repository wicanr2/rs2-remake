# 001 Rust 重製第一關垂直切片

狀態：CONFORMED（2026-11-05）。A0～A6、A8 通過。A7 真人試玩由使用者決定不做，手感相關的值（補間門檻、顯示延遲、自動重複）維持初值，沒有真人驗證。

證據：第一輪獨立審查的 3 個阻擋項、17 個應改項都已回機器碼核對並處理；逐幀收據 `trace_dm1`（640 筆）與 `boss1_kill`（1192 筆）各經兩個獨立容器重跑，雜湊相同；第一幀資料段與平面傾印 `a0_demo`、`a0_newgame`。收據說明見 [10](../re/10-dynamic-receipts.md) 第 8 至 10 節。

## 範圍

第一關可玩：載入素材、背景捲動、實體生成與移動、玩家移動與開火、碰撞、血量、道具、頭目、過關判定、過關連爆。用 `DM1.LCK` 重播與原版逐幀對拍。

不含：開場、選單、過場、第二到第四關、音樂、音效、單色與 CGA 模式、JOYMOUSE、破解層。

雙人分支在幀流程裡，隨逐函式移植進 `rs2-game`，這一版不驗收。

## 輸入

| 檔案 | 用途 |
|---|---|
| `MY.GO`、`SHT1.GO`、`BH1.GO` | 圖庫 |
| `S.EXE` | 解包後取資料段 |
| `DM1.LCK` | 重播測試 |

雜湊以 [source-manifest.json](../../source-manifest.json) 為準，預期值寫進 Rust 原始碼。解包映像另驗 SHA-256 `8475b41b45507ab10f0430238e5d20a11563b7d1b202997680f73a7cab34de72`。任何一個不符就拒絕啟動，錯誤訊息寫出檔名與預期雜湊。

## 素材來源

啟動時從玩家自備的原版即時解碼，repo 與發行包不收原版位元組。`S.EXE` 有兩層 LZEXE 與 `0969:0100` 包裝碼，解包在 Rust 內重做，規則同 `tools/unpack_exe.py`。

HD 素材是獨立的本機資料夾，以 `--hd <路徑>` 指定，沒給就顯示原版圖。沒有原版就不能玩，這一版沒有替代美術。

Rust 1.99.1，edition 2024。

## 實作方法

`rs2-game` 依機器碼重寫，`docs/re/` 只當索引。審查抽查時，資料層的文件可靠，流程時序與初始狀態有多處誤差，所以兩者不一致時以機器碼為準，並回頭修文件。改寫的方法與完成條件見[規格 004](004-rewrite-and-delivery.md)。

| 規則 | 內容 |
|---|---|
| 狀態 | 有型別的 `State`：特效、敵彈、玩家彈、敵人、景物、玩家、標題、流程、各關背景、繪製參數、音效、格網、展示錄影 |
| 表格 | 樣板、腳本、調色盤、形狀、時間表由 `Tables::parse` 從 `S.EXE` 解包映像解析，雜湊不符就拒絕，不抄進 Rust 原始碼，解析完不留原始記憶體 |
| 表外讀寫 | 原版的表外讀寫是可觀察行為：敵彈 G2 的列基底別名到 G1，`bullet_slot_carry` 會寫到 `34B1h`，`armor_cell_index` 會讀到 `248Eh`。每一項寫成有名字的規則。格網的越界別名是 16 位元位址運算，所以 `grid.rs` 保留原版的格網位址 |
| 函式 | 有意義的名字，文件註解保留原版位址。IDA 自動名稱不當語意依據 |
| 暫存器 | 沒有。依賴殘值的地方逐一查過呼叫端，改成參數與回傳值，例如 `sub_11375` 第一次執行改寫 `al`，血條第一格的顏色取自它 |
| 對拍 | `rs2-trace` 的 `Mirror` 把 `State` 疊回 64 KB 資料段，和原版傾印逐位元組比。原版位移只在 `rs2-trace`、`tables.rs` 與 `grid.rs` |
| 查機器碼 | `tools/q.sh`，完整上下文看 `workspace/ida/s_disasm.txt` |

`State` 之外、不影響 A2 比對的狀態有：循環的相位（這一步是第一頁或第二頁）、暫停旗標、`sub_11375` 把自己改成 `retn` 的旗標、目前的圖庫組、前端用的物件世代計數、`bullet_slot_carry` 開啟時的敵彈槽號輔助陣列、強化選項。

中斷處理：

| 中斷 | 移植內容 |
|---|---|
| INT 9（`1A83Dh`） | 全部移植成 `int9(scancode)`：按鍵表 `dseg:A8CBh + 掃描碼`（按下 1、放開 2）、`sub_1A8F4` 秘技序列、`sub_1A9B5` 旗標、`sub_1A891` 音效開關 |
| INT 8（`1A7B5h`） | 不進 `step`。時基由前端負責。`1A7DAh` 的反竄改分支在 `byte_273AD` = `Y` 時不執行，全程維持 `Y`（[10](../re/10-dynamic-receipts.md)）。`sub_14D8C` 的 JOYMOUSE 輪詢在 `byte_1DAAC` = `N` 時不影響按鍵（`14E40h`），這一版不支援。`word_1D3A8`、`word_1D3AE` 只有密碼函式讀 |

## 一步的邊界

`step` 對應原版一個邏輯幀，每秒 9.10 次（18.2065 Hz 除以 2），也就是 `sub_10CD0` 主迴圈（`10D29h` 至 `10D8Bh`）的一半。

```text
第一步：int9(輸入)；sub_19A37（頁 = 8000h）；sub_10FEA；sub_10EEA
第二步：int9(輸入)；sub_19A88（頁 = 0）；sub_10EEA；
        sub_10ECB（Esc 暫停）；sub_10D99（熱鍵）；sub_10D8D（存活）；結束判斷；
        byte_1CFAD = F 時播一次連爆，第 21 輪以 C 離開
```

- `sub_10EEA` 內的 `sub_11097(2)` 等待由前端取代，調色盤呼叫變成繪製命令。
- `sub_10ECB` 在原版是阻塞迴圈，這裡改成暫停旗標：之後的 `step` 只處理 `int9`，等 `dseg:A8CCh` 離開 2 才恢復，並清 `A8CCh` 與 `A862h`。
- 取樣點是 `sub_11097(2)` 之前（第一關 `10F98h`、`10FE3h`），在 `10F26h` 的 `sub_10C3D` 與 `10F2Eh` 的計數釘回之前。`rs2-trace` 在這一點輸出。

熱鍵移植 Ctrl+Q、Ctrl+R、Ctrl+C（`sub_10D99`），Ctrl+D 與 Ctrl+W 這一版不做。

## 初始狀態

`rs2-game` 提供兩個入口：

| 入口 | oracle（主迴圈頭 `10D29h`，計數 0） |
|---|---|
| `Start::Demo` | `a0_demo/demo_entry.ds`：冷啟動、標題不按鍵進 DM1 |
| `Start::NewGame { difficulty }` | `a0_newgame/newgame_entry.ds`：標題按空白、不經選單。難度字維持映像值 0、0；選單不在本切片，`difficulty` 給值時依 `12754h` 至 `127A4h` 寫入 |

第一幀前的狀態依序建立（`rs2-trace/tests/power_on.rs` 逐欄對映像）：

1. 解包映像的資料段，補零到 64 KB。
2. 載入 `DM1.LCK` 到 `dseg:AAE2h`。兩個入口都載（`10CF9h` 的 `sub_1BED5`）。
3. 寫入下表，這些值由不移植的標題流程設定。
4. 移植 `10CFCh` 至 `10D11h`：`byte_1CFDB` = `A`、`sub_11112`、`sub_10E33`（內含 `sub_18599`、`sub_14F47`、`sub_158BA`）、`byte_1CFAD` = `N`、`word_20B7A` = 0。`sub_113B2`、`sub_1149F`、`sub_10B65` 的載入改成繪製命令。

| `byte_1CFDC`（`41Ch`） | 示範 `Y`，新局 `N` | 標題 `sub_11556` | `14497h`、`10DA6h` |

傾印與重建結果的差異只能落在下列豁免範圍，A0 把這張表寫成程式檢查。範圍外有任何一個位元組不同，就是初始化漏了東西。

## 輸入模型

```rust
pub struct Input<'a> { pub scancodes: &'a [u8] }
```

`scancodes` 是上一步到這一步之間送達的 set 1 掃描碼，含放開碼與自動重複。`step` 開頭依序餵給 `int9`。

這個模型直接涵蓋審查指出的依賴：`byte_273A9` 是「右 Shift 按住期間有 INT 9 事件」，充能與砲座旗標都看它（`14621h`、`1462Fh`、`14642h`），所以要保留事件本身，不能只存按鍵狀態。

- **示範模式**：`sub_14497` 照舊，每幀清方向鍵與 `byte_274C1`，設 `byte_273A7` = `Y`、`byte_273AA` = `N`，再依 `dseg:AAE2h[計數]` 設旗標。
- **按鍵對照**：`rs2-play` 把 SDL 鍵轉成不帶 `E0h` 前綴的 set 1 碼：方向鍵 `48h`、`50h`、`4Bh`、`4Dh`，斜向 `47h`、`49h`、`4Fh`、`51h`，右 Shift `36h`，`/` `35h`，Esc `01h`。
- **自動重複**：原版靠鍵盤硬體產生重複碼，靜態沒看到 `out 60h` 改設定。`rs2-play` 自己產生，只重複最後按下的鍵，初值延遲 500 毫秒、每秒 10.9 次（IBM AT 鍵盤預設值），並忽略作業系統的重複事件。
- **對拍時的對應**：收據的 `sc` 欄是上一個取樣點到這一個取樣點之間送達的掃描碼，直接當這一步的 `scancodes`。`rs2dyn play` 在取樣點之後立刻送鍵，落在幀尾的等待裡，所以一定早於下一幀的 `sub_14458`。用 `tap` 以時間送的鍵可能落在幀中，只有秘技序列這樣送，它在 `int9` 內就完成，不依賴幀內時機。
- **熱鍵的時序差**：第二頁尾端的 Esc 暫停（`sub_10ECB`）與熱鍵（`sub_10D99`）在取樣點之後才檢查。原版看得到同一步取樣後送達的鍵，重製要到下一步開頭才收到，晚一步生效。差分收據只在第一頁取樣之後送這些鍵。玩家輸入在下一步開頭才讀，兩邊一致，不受影響。

## 繪製模型

`step` 回傳 `Frame { draws, exit }`。音效參數 `byte_2684F` 照舊寫進狀態（`Sound`），音效進範圍時再接。`draws` 是這一幀依原版順序的繪製命令，每種 blit 變體（[12](../re/12-stages-presentation.md) 第 2.3 節）一種命令，參數取自移植後的 `dseg` 寫入。邏輯不讀顯示記憶體，第一關唯一讀 G3 的 `1840Eh` 只在第三關（審查 F5），所以模擬不依賴接收端。

| 接收端 | 用途 | 準確度 |
|---|---|---|
| `VgaSink` | 補間關閉的原版圖模式。4 個 64 KB 平面，頁 0 與 8000h，暫存區 A `1F40h`、B `9F40h`，移植 AND 遮罩、OR、覆寫與 latch 複製 | 逐像素 |
| `LayerSink` | 補間與 HD。每個物件獨立畫，原版圖轉成 RGBA 或換 HD 圖 | 由人判讀 |

下列狀態跨幀存在，只由 `draws` 累積，所以 `Frame` 不必重複傳：

| 狀態 | 行為 | 位址 |
|---|---|---|
| 介面列 190～199 | 每幀清除只清 190 列，這區不清 | `sub_19CF9`、`1A317` |
| 血條 | 只在受擊時畫，`xor di,8000h` 同時寫兩頁，開場沒有血條，重新開始仍殘留 | `1452Bh`、`11336h`、`1935Ah` |
| 暫存區 A | 五層背景來源，`sub_10B65` 寫一次 | `10B73h` 至 `10C39h` |
| 暫存區 B | 頭目合成圖與損壞貼片累積 | `10C3Dh`、`15DFEh` |
| 幀計數 | 每幀只寫平面 3，位置 (144,191) | `1100Ah` |
| 背景超讀列 | 波浪讀來源列 38、39，遮罩讀來源列 285，都超過圖高（[12](../re/12-stages-presentation.md) 第 5.1 節）。傾印證實內容是 0 | `16350h`、`163A1h` |

`LayerSink` 用同一批命令維持自己的圖層：暫存區 B 保留累積清單，介面列保留到下次更新。

## 修正原版缺陷

使用者 2026-11-04 決定修正。`rs2-game` 用一組 `Fixes` 旗標控制，遊戲預設全開，對拍工具全關。

| 旗標 | 原版行為 | 修正後 | 影響範圍 | 等級 |
|---|---|---|---|---|
| `bullet_slot_carry` | 敵彈格值是形狀值加槽號，`and 0Fh` 後回繞。槽 15 把 0 寫到 `34B1h`（槽 15 記錄的 y），槽 16～19 刪掉槽 0～3，擊中的那顆留在池裡（[11](../re/11-entities-combat.md) 第 5.4 節） | 另存真正的槽號，刪除對象以它為準 | 第三、四關頭目戰會觸發，本切片碰不到 | 動態已證實 |
| `armor_cell_index` | 雷射與砲座碰到裝甲格 `FEh` 時取到指標 0，把傷害字組寫到 `dseg:0020h`（第 5.3 節） | `FEh` 格不寫傷害，與一般子彈路徑相同。指向已釋放槽的格值同樣不寫 | 第四關頭目，沒有玩家可見的影響 | 動態已證實 |
| `seeker_spawn_leak` | 玩家彈池已滿時 `sub_16578` 放棄生成，`16650h`、`16708h` 仍加 2，同一關內 `B` 武器可能因此停火（第 6.5 節） | 依實際生成數加 | 有 `B` 武器的關卡 | 靜態已證實，動態未觸發 |

新發現的缺陷比照辦理：先留原版行為與對拍，再加旗標修正。

審查還找到兩個行為：砲座在按住且有事件的幀不清 `byte_1DAA5` 而多發、敵彈 G2 的列基底別名到 G1。這些影響手感與保存價值，也沒有證據顯示是製作者不要的結果，所以照原版，不加旗標。

|---|---|
| 畫面補間 | 使用者決定要有，預設開。模擬仍是每秒 9.10 次，`LayerSink` 依物件編號在前後兩個邏輯幀之間線性內插 |
| 物件編號 | `(池別, 槽號, 世代)`。世代在槽被生成函式配置時加 1，不屬於原版狀態。敵彈池的槽可能在同一幀釋放再重用（`16CEAh`、`17382h`），沒有世代會內插出殘影 |
| 補間例外 | 物件剛出現、消失、位移超過門檻的那一幀不內插，直接畫新位置。門檻初值 48 像素（腳本碼 0Ah 一幀走 6 欄），試玩後定案 |
| 背景層 | 依各層循環長度算環繞後的位移再內插（波浪每幀 16 像素、模 320），不當成瞬移 |
| 閃爍 | 受擊閃白、噴焰依頁交替，照原版的邏輯幀切換，不內插 |
| 延遲 | 內插多一個邏輯幀（約 110 毫秒）的顯示延遲。要改手感可以對玩家機改用外插，屬前端，不影響模擬 |
| 幀計數 | 原版發行版畫在畫面底部。預設關閉，工具列可打開。數字字型由重製自繪，原版用 BIOS ROM 字型（`F000:FA6Eh`），不屬於遊戲素材 |
| 工具列 | 頂端可隱藏，含補間開關（F1）、幀計數開關（F2）、原版圖與 HD 切換（F3）、視窗倍率（F4，2 到 5 倍）、隱藏（F10），滑鼠可點。設定存本機。這些鍵不送進遊戲。沒有 CJK 字型，所以標籤是 ASCII，點陣自繪 |
| 過關 | 這個切片只有第一關，過關顯示 `STAGE 1 CLEAR`，按 Enter 重新開始 |

## 驗收

| 編號 | 項目 | 通過條件 |
|---|---|---|
| A0 | 初始狀態 | 兩個入口的第一幀資料段（`Mirror` 產生）與傾印相同，差異只出現在「初始狀態」一節的豁免範圍 |
| A1 | 格式跨實作 | `MY.GO`、`SHT1.GO`、`BH1.GO` 每個圖庫項目的解碼結果，Rust 與 `tools/export_pixel_hashes.py` 各自計算的雜湊相同。雜湊對象是 `u16le 寬 ‖ u16le 高 ‖ 解碼後的原始位元組`。解包映像雜湊相同 |
| A2 | 重播對拍 | `Fixes` 全關，`Start::Demo` 跑 640 幀，`rs2-trace` 輸出與 `trace-dm1.jsonl` 用 `tools/dos/check_trace.py --diff` 比對，忽略 `emu` 欄位，全部相同 |
| A2b | 修正隔離 | 每個旗標一組合成情境的單元測試：直接擺出觸發條件，旗標關時重現原版結果，旗標開時得到修正結果。DM1 的敵彈最大槽號只有 8，也碰不到第四關與 `B` 武器滿池，不能只跑重播。另跑 `Fixes` 全開的 DM1 與 `boss1_kill`，兩者都要和全關相同，不同就列出那些幀 |
| A3 | 雜湊拒絕 | 改任一輸入一個位元組，程式拒絕啟動，有負對照測試 |
| A4 | 正常玩家路徑 | `Start::NewGame` 餵 `boss1_kill` 收據 `sc` 欄的掃描碼（含秘技序列與每幀開火），從第一關打到頭目，核心在第 1152 筆（n=1151）死亡，過 20 輪連爆，以 `C` 離開。1192 筆逐幀 JSONL 全部相同。這條路徑走真實的 INT 9，不繞過輸入。玩家不動，與真人遊玩的差異由 A7 補 |
| A5 | 畫面 | 補間關閉，固定幀的 4 個平面 64 KB 內容與顯示的 16 色 6 位元 DAC 都和傾印相同：`a0_demo` 的 `demo_n0`、`n1`、`n99`、`n299`、`n620`、`n622`、`n639`，以及 `a5_boss` 的 12 個時點（頭目合成圖、損壞貼片、血條、連爆）。平面 3 排除幀計數矩形：兩頁的列 191～198、位元組欄 18～22。新局入口的第 621 步前不比暫存區 B，那裡是過場殘圖，`sub_10C3D` 才清掉。不經過 RGB 換算，所以 6 位元轉 8 位元的式子不影響結果 |
| A5b | `LayerSink` 等價 | 原版圖、不補間時，`LayerSink` 與 `VgaSink` 在 DM1 全部 640 幀與頭目擊殺全部 1192 幀每像素相同。每幀先以 alpha 0、0.25、0.5、0.75 渲染，再比 alpha 1.0，結果不變，證明補間不污染畫面狀態。HD 模式由人判讀 |
| A6 | 前端開關 | `rs2-play` 在 `SDL_VIDEODRIVER=dummy` 下，對補間與幀計數的四種組合各跑同一段輸入，在主迴圈內計算每步資料段雜湊，四組完全相同 |

| A8 | 差分模糊 | `tools/dos/gen_fuzz.py` 產生的 43 份隨機輸入收據，dosgolem 與 Rust 逐幀相同，含離開碼與定期的整段資料段比對。涵蓋朝左武器、追蹤彈、掃射、玩家死亡、八方向鍵、熱鍵、Esc 暫停。第一關可達而未走到的函式只有玩家 2 與已判定不可達的項目，清單見 [10](../re/10-dynamic-receipts.md) 第 11 節 |

單元測試與 A1 通過不算完成。A0、A2、A4、A5、A5b、A8 都通過才能標 CONFORMED。

## 失敗模式

- 缺檔或雜湊不符：拒絕啟動。
- HD 資料夾缺某張圖：該張退回原版圖並在畫面標記，啟動日誌列出缺的項目。
- 重播與原版不同：`rs2-trace` 回報第一個不同的幀與欄位路徑。
- 移植時遇到解釋不了的機器碼：退回 DRAFT 記下來，不猜。

## 權利邊界

重製程式碼採 RRSAL-1.0。原版素材與 HD 圖不進 repo 與發行包，`tools/leak_check.py` 在每次推送前把關。`rs2-game` 是原版機器碼的逐函式移植，與素材同樣有權利疑慮，大宇資訊的權利現況未查證。repo 維持私人，對外公開程式碼或展示前先問使用者。
