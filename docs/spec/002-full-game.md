# 002 全遊戲流程

狀態：CONFORMED（2026-11-05）

證據：規格 001 的方法在第一關通過全部對拍，差分測試沒有找到移植錯誤。本規格沿用同一套方法，把對拍擴大到每個等待點的完整狀態，所以文件與機器碼的誤差會直接在比對時現形。流程入口與等待點的盤點來自 `workspace/ida/s_disasm.txt`。

## 範圍

E 模式（VGA）的完整遊戲：標題、開場動畫、示範、選單（難度與玩家數）、第一到第四關、關間過場、片尾、雙人。

不含：音樂與音效（規格 003）、CGA 與 MGA（另立規格）、文字選單與密碼畫面、JOYMOUSE。

## 輸入

`S.EXE`、`MY.GO`、`SHT1.GO` 到 `SHT5.GO`、`SHT4.GOT`、`BH1.GO`、`BH2.GO`、`BH4.GO`、`MAP.GO`、`J1.GO` 到 `J4.GO`、`BEG1.BD1` 到 `BD4`、`SHT.SCN`、`SHT.SCR`、`DM1.LCK`、`DM2.LCK`。雜湊預期值在 `rs2-formats`，來源是 [source-manifest.json](../../source-manifest.json)，不符就拒絕啟動。

## 實作方法

沿用規格 001「實作方法」：照機器碼逐函式移植，平坦 `Dseg`，暫存器是欄位，只移植 E 模式分支。新增的部分如下。

| 項目 | 規則 |
|---|---|
| 協程 | 原版到處有阻塞等待，所以 `rs2-core` 跑在一個 `async` 協程裡。會等待的函式是 `async fn`，`sub_11097` 與忙等迴圈是 `.await` 點，其餘函式維持同步。對外介面仍是 `Game::step`，一步是一次等待 |
| 時間 | `Frame.ticks` 是到下一步要等幾個 18.2065 Hz 的 tick，前端照它排程。模擬本身不花時間，所以 `sub_11097` 進來時計數一定是上次歸零後的值 |
| 忙等 | 原版等按鍵或等計數的迴圈改成 `poll_tick().await`，每個 tick 檢查一次 |
| INT 8 | `Core::int8` 只做對 `dseg` 的效果，每個 tick 一次 |
| INT 9 | 掃描碼在等待恢復時處理，等於原版在等待期間收到。第一關的熱鍵時序差因此消失 |
| 載入 | 檔案載入不移植，只記圖庫組切換（`loader.rs`）。`DMn.LCK` 寫進 `dseg:AAE2h`，`SHT.SCN`、`SHT.SCR` 放 `GameFiles`，讀取端自己索引 |
| 跨關狀態 | 全部在 `Dseg`，流程函式照原版傳 `dx` 離開碼 |
| 入口 | `Game::from_snapshot(檔案, 資料段, Entry, Fixes)`。`Entry::Title` 是正式遊戲，資料段來自開機狀態表；各關入口給對拍與除錯用 |

開機狀態：原版在 `sub_11556` 入口的資料段，減去啟動選單、密碼與 DOS 記憶體配置的影響，整理成 `rs2-core` 內的修補表，不把傾印放進 repo。差異分類的規則同規格 001「初始狀態」。

`sub_10FEA` 在第一次進 `sub_10CD0` 時呼叫 `sub_11556`，重製從 `sub_11556` 開始，不走這條路。

## 全流程對拍

這是本規格的主要 oracle。`rs2dyn waittrace` 在 `sub_11097` 離開等待的位置（`1109Dh`）記錄，一次等待一筆：

| 欄位 | 內容 |
|---|---|
| `n`、`ret`、`cx`、`frame` | 序號、呼叫端位址、等待 tick 數、幀計數 |
| `sc` | 上一筆之後送達的掃描碼 |
| `vram` | 4 個平面共 256 KB 的 SHA-256 |
| `dac`、`start` | 256 色 DAC 與屬性表的 SHA-256、顯示起點 |
| 資料段差異 | 另存二進位檔，每筆只存和上一筆不同的位元組，重建後逐位元組比對 |

重製在同一點（`Game::step_full` 的 `on_wait`）比對。資料段的豁免範圍是 `rs2_core::DS_EXEMPT`，每一段要寫理由。第一個不同的筆數由 `tools/dos/wait_locate.sh` 重跑取得完整平面，定位到偏移與最後寫入的命令。

幀計數的字型在對拍時用 dosgolem 傾印的 BIOS 字型（只留本機），所以畫面比對不再需要排除矩形。

## 已知差異

| 原版 | 重製 | 為什麼 |
|---|---|---|
| 啟動文字選單、SETSW、密碼畫面 | 不做，直接進標題 | 防拷與硬體設定，不屬於遊戲內容 |
| 磁片提示與讀檔失敗重試 | 不做，啟動時驗過全部檔案 | 原版靠軟碟，重製沒有這條路徑 |
| 忙等迴圈即時反應按鍵 | 最多晚一個 tick | 模擬以 tick 為最小單位，不影響狀態 |
| Ctrl+W 傾印畫面 | 不做 | 開發工具，寫檔不屬於模擬 |

| 第四關 Ctrl+C 留下的實體帶著超出 `SHT5` 的圖號進片尾，表外記憶體被當圖畫 | 不畫 | 內容取決於記憶體殘值，兩幀就消失 |

對拍時用圖庫記憶體傾印（`wait-wt_flow.bk`、`VgaSink::set_bank_dump`）重現越界圖號，證實真因，比對不放寬。正式路徑沒有這份傾印。

規格 001 的「修正原版缺陷」三個旗標在本規格仍然適用：`bullet_slot_carry` 在第三、四關頭目戰生效，`armor_cell_index` 在第四關頭目生效。另加一個：

| 旗標 | 原版 | 修正 |
|---|---|---|
| `no_hit_hang` | 第二關幀 260 的 `sub_1316C`（`131C9h`）在 `byte_1CFAA` 還是 `N` 時跳回開頭，永遠卡住。這個旗標只有第一次重畫血條時才寫成 `Y`，所以到這裡都沒被打中就會卡（`hang_s2`，動態已證實卡死本身） | 照常往下走 |

## 失敗模式

- 缺檔或雜湊不符：拒絕啟動，訊息寫出檔名與預期雜湊。
- 移植時遇到解釋不了的機器碼：不猜，記進 `WORKLOG.md`，回到機器碼或多取一份收據。
- 比對不同：回報筆數、呼叫端、欄位或偏移。不放寬比對。要新增 `DS_EXEMPT` 必須寫明該範圍只有哪些函式讀寫。
