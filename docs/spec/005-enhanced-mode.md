# 005 強化模式與設定介面

狀態：CONFORMED（2026-11-06），全部選項。驗收 E1 至 E7 都有測試通過；手感、平衡與難度沒有真人驗證。

使用者 2026-11-05 定位：這是台灣自製的 R-Type 類射擊遊戲，有文化保存的必要。所以原版規則永遠保留，強化全部是選項，可以從工具列設定。

本規格的內容不是從原版導出的，全部屬於 remake-owned。行為的依據是這份規格與單元測試，沒有原版收據可以對拍。

## 原則

| 項目 | 規則 |
|---|---|
| 原版模式 | 所有會改變規則的選項關閉時，全部收據逐位元組相同。`tools/rust.sh verify` 永遠用這個狀態跑 |
| 決定性 | 強化開啟時，同樣的輸入與選項仍得到同樣的結果 |
| 預設值 | 改變規則的選項預設關閉。AI 強化使用者明確要求預設關閉。只影響顯示與聲音的選項預設開啟 |
| 依賴 | 改變規則的選項等對應領域重寫完才做（規格 004），不在平坦資料段上寫 |
| 標示 | 有任何改變規則的選項開著時，狀態列顯示「強化規則」。截圖與錄影看得出來不是原版 |
| 原版美術 | 製作者署名與商標不動。新特效用既有素材或程式產生，要新美術時另走 HD 流程 |

改變規則的選項在遊戲中切換時，戰場大小等下一次進關才生效，其他立刻生效。

核心的介面是 `Game::set_rules(Rules)` 與 `Game::set_split_held(player, held)`。`Rules` 全關等於原版，不進資料段。前端的 `Settings::rules()` 只把 `options.rs` 標 `implemented` 的選項算進去。展示錄影播放時一律當選項全關（`Core::rules`），因為錄影是原版的輸入，強化規則會讓它對不上。

## 戰場大小

原版四關的生成表共 342 列，154 列在畫面右緣 x=320（欄 40）生成，只有 9 列在欄 40 右邊，其餘在畫面內或上下方（靜態已證實，讀 `dseg:41BEh`、`54FEh`、`68E0h`、`7922h` 各列樣板的 w9、w10）。玩家子彈也在原版邊界附近消失，碰撞格網只有 40 欄。所以只拉遠鏡頭看不到更多敵人，要真的加大戰場。

加大的是水平方向。背景美術只有 190 列高，往上下延伸要新美術，所以垂直維持原版的 19 列遊戲區。橫向捲軸射擊多看到的是前方，這也是加大視野的主要用途。這是代理的決定（2026-11-06），屬於 remake-owned，使用者可以改。

| 遊戲區（邏輯像素） | 320×190 | 384×190 | 480×190 |
| 欄數（碰撞格網、繪製頁、背景暫存區） | 40 | 48 | 60 |
| 玩家活動範圍 | 欄 1 至 33 | 欄 1 至 41 | 欄 1 至 53 |

| 敵人 | 分自由飛行與景物綁定兩類。自由飛行的敵人：生成在右緣（x ≥ 320）的列整體平移到新右緣，在畫面內與上下方生成的列依比例平移 x（x × 新寬 ÷ 320，往零取整）。時間表與腳本內的相對位移不改，所以進場距離變遠，到達玩家面前的時間會晚，接受這個差異。景物綁定的敵人見下一節 |

### 景物綁定的敵人

第三關的地面砲台與第二關沿柱子移動的敵人，位置是對著景物設計的。地圖靠左對齊，畫面第 c 欄在各寬度是同一個地圖欄，所以這類敵人照自由飛行的規則平移，會和地形錯開。

| 項目 | 規則 |
|---|---|
| 認法 | 模式 `Y`（每幀隨景物左移 1 欄），或第三關腳本開頭是四組「往左一步、停一步」（每兩幀 1 欄，和地圖同速）。頭目列不算 |
| 列數 | 第一關 4、第二關 44、第三關 41（模式 `Y` 18、地圖速度 23），第四關與片尾沒有。由 `entity::tests::real_timetables_inventory` 固定 |
| x ≥ 40 | 提前 lead 幀生成在新右緣，lead 是多出來的欄數乘景物走 1 欄的幀數（模式 `Y` 為 1，地圖速度為 2），生成幀不夠提前時從第 0 幀起。提前這段只隨景物移動，不讀腳本、不推動畫、不擲亂數、不開火，可以被打死，也會撞玩家。到原版生成幀時剛好在原版的地圖欄，之後照原腳本走（`entity::Approach`） |
| x < 40 | x 不放大，在原版生成幀生成 |
| 離場 | 不套用離場延伸，腳本結束照原版釋放 |
| 敵人池 | 仍是原版的 15 槽。提前生成多佔槽，玩家左右移動並開火時，第三關景物綁定列因池滿放棄的次數比 100% 多 2 至 3 次 |

`field_terrain_bound_enemies_stand_on_the_same_map_columns_as_in_100_percent` 逐步比對第一、二、三關畫面欄 0 至 39 內同一個敵人的欄，120% 與 150% 都和 100% 相同。

## 射擊

原版一次按放只射一發，按住不連射。大掃射要裝滿兩座砲座，按住 14 個鍵盤事件以上，也就是靠鍵盤自動重複計數（`docs/re/11-entities-combat.md` 6.1）。手把沒有自動重複，這是原版操控不佳的主因之一。

| 選項 | 行為 |
|---|---|
| 波動砲充能 | 按住開火鍵累積充能，以邏輯步計數，不看鍵盤事件。不需要砲座。畫面底部顯示充能條。放開時依充能量射出三級波動砲：第一級沿用普通彈加大，第二級穿透，第三級沿用大掃射的穿透彈加上全高度判定 |
| 按住連射 | 按住開火鍵時每 2 個邏輯步射一發普通彈。和波動砲同時開著時，連射照常，放開才結算充能 |
| 砲座像 Force | 原版的轉向鍵維持前後轉向。新增「分離」鍵：砲座脫離機身往前飛，碰到敵人造成傷害並擋子彈，再按一次收回。可從前方或後方接回，接回的方向決定朝向 |
| 打擊回饋 | 命中閃白、大爆炸時畫面短暫震動、射擊與爆炸音效加重。只在顯示與音訊層，由模擬回報事件，不改判定 |

實作的初值與行為（`crates/rs2-game/src/player/enhanced.rs`），數值都是常數，使用者試玩後調：

| 項目 | 內容 |
|---|---|
| 波動砲門檻 | 按住 4、8、12 個邏輯步（約 0.44、0.88、1.32 秒）為三級，HUD 充能條三等分對齊 |
| 波動砲傷害 | 第一級 2，用 `K` 武器的大彈（命中消失）；第二級 3，穿透；第三級沿用大掃射穿透彈 3 |
| 第三級全高度 | 七顆穿透彈從列 0 起每 3 列一顆（列 0、3、6、9、12、15、17），涵蓋列 0 至 18。原版大掃射是列 1、4、...、16，漏掉列 0 |
| 波動砲按鍵 | 新按那一步照原版射一發普通彈，按住的步充能加 1，放開依級數射出 |
| 連射 | 新按射一發，之後每 2 步一發，砲座同步開火。只開連射時原版大掃射保留，以邏輯步累積 |
| Force | 分離鍵按下的邊緣動作，兩座一起脫離，沒有單座分離。發射每步 4 欄，離起點最多 16 欄。收回每步 4 欄、20 像素。傷害 2（附著時原版是 1）。機身碰到砲座也接回，砲座在機身右邊朝右，否則朝左。發射後 3 步內不因接觸而接回 |
| 細步 | 方向和上一步不同的那一步走半步（1 欄、5 像素），相同的步走整步。邏輯 9.1 Hz，輕點和按住在一步內分不出來，所以用「新按走半步」達成微調。按住 N 步比原版少走半步。半列時碰撞列取機身上緣所在的列，本體髒格多標一列 |

細步對奇數欄的查證：移動界限 `col > 1`、`col < 33` 依賴奇數欄，細步改成夾在 1 與 33 之間。G3 重繪、砲座偏移、子彈生成、敵人瞄準都沒有奇偶假設。blit 本身有沒有針對奇偶欄的路徑沒查，只靠接收端輸出判斷。

## AI

實作在 `crates/rs2-game/src/ai.rs`，狀態在 `AiState`，有自己的亂數（xorshift32），原版亂數表索引不多走一步。常數在檔案開頭。

| 選項 | 行為 |
|---|---|
| 瞄準更準 | 瞄準彈與寬彈照原版選最接近的樣板，再配一條逐幀路徑朝玩家形狀中心走。預判玩家最近一幀的移動量乘 3 幀，欄夾 ±4、列夾 ±3。只吐腳本本來就有的移動碼，彈速和原版同級 |
| 火力加強 | 原版這一幀沒開火的普通敵機另擲骰子：會開火的每幀額外 4、5、6、8%（EASY 到 HARDEST），原版從不開火的瞄準彈敵機 3、4、5、6%。頭目不受影響，場上已有 10 顆敵彈就不加。沒修正 `bullet_slot_carry` 時全部敵彈只用槽 0 至 14，不會更常撞上格值進位缺陷 |
| 敵人會反應 | 普通敵機閃避前方 7 欄內、列重疊的玩家彈，一生最多 6 步。腳本停著且玩家在水平 12 欄內時朝玩家的列走一步，一生最多 5 步。頭目不動，只用既有移動碼 |
| 頭目新招式 | 見下表。週期每升一級難度縮 4 幀，下限 24。離玩家欄差加列差小於 7、發射點出畫面或過關旗標已設時不出招。新招式先騰出敵彈槽（先放反彈球，再放一般彈），不比原版更密 |

| 頭目 | 招 | 起始幀 | 週期 | 內容 |
|---|---|---|---|---|
| 第一關 | 三連瞄準彈 | 24 | 30 | 3 發 `F`，相隔 3 幀，每發重新瞄準 |
| 第一關 | 環形彈 | 48 | 72 | `<`，八方向各一顆 |
| 第二關 | 瞄準寬彈 | 30 | 40 | `B` |
| 第二關 | 五連扇 | 60 | 64 | `L`，西、西北、西南、北、南 |
| 第三關 | 四連瞄準彈 | 40 | 48 | 4 發 `F`，相隔 3 幀 |
| 第三關 | 三向彈 | 70 | 80 | `X`，北、西、西北 |
| 第四關 | 三連瞄準彈 | 30 | 36 | 3 發 `F`，相隔 3 幀 |
| 第四關 | 環形彈 | 54 | 72 | `<` |

全開時敵彈合計對照（原版 對 新招式，模擬追擊機器人）：第一關 6522 對 7618，第二關 702 對 1119，第三關 17428 對 13645，第四關 63109 對 43796。第三、四關原版彈幕本來就塞滿敵彈池，騰槽後總量反而變少。第四關圓盤在模擬裡選項全關與全開都沒被打倒，所以第四關打得贏是推論：選項不改頭目耐久與移動。

## 無敵

使用者要求的選項。使用原版已有的作弊判斷（`word_273A5`：`Y` 時不減血），開啟時狀態列顯示「無敵」。

## 操控

原版操控不佳的原因與對應：

| 原因 | 對應 |
|---|---|
| 邏輯一秒 9.1 步，按鍵到畫面最多 220 毫秒 | 玩家機預測（規格 004「體感」） |
| 兩步之間的短按會漏 | 短按保留（規格 004「體感」） |
| 一步走 16 像素，難以微調 | 細步移動：水平 8 像素、垂直 5 像素一步，邏輯步內走兩次判定，總速度相同 |
| 充能靠鍵盤自動重複 | 波動砲充能以邏輯步計數 |
| 只能用鍵盤 | 手把，見下節 |
| 鍵位固定，右 Shift 開火對部分鍵盤不便 | 鍵盤可重綁，見下節 |

- 設定存使用者設定目錄，寫入是原子的。手把指派不存，裝置編號重啟會變。
- 中文字型用 Noto Sans CJK TC（OFL），只把介面用到的字烘成點陣放進程式，發行包帶 OFL 全文。
- Android 用同一個設定畫面，字放大，手指點選。

## HD 介面

使用者 2026-11-05 要求：介面也要 HD，要現代化。

原版的介面只有第 190 到 199 列的黑條，上面一條 8 格血條與幀計數，沒有武器、砲座或充能的顯示。HD 模式要重新設計，原貌模式維持 1990 年的樣子，這也是保存的一部分。全部只改顯示，不影響模擬，不呼叫生成模型。

| 項目 | 原貌模式 | HD 模式 |
|---|---|---|
| 遊戲內 HUD | 原版血條與黑條，一個像素都不動 | 下面「HUD」一節 |
| 標題選單的選中列 | 原版的反相 | 文字用 HD 圖不反相，選中列後面畫圓角高亮條 |
| 打擊回饋 | 不生效，補間關閉時要逐像素等於原版 | 依選項生效 |
| 工具列與設定畫面 | 現代化，兩種模式相同，它們不在遊戲畫面內 | 同左 |

署名與商標不動：`大宇資訊 1990` 橫幅、製作者名單、SOFTSTAR 標誌照原位顯示 HD 圖。

### HUD

玩家機在畫面上時，蓋在 HD 畫面底部 40 像素（對應原版第 190 到 199 列）。標題與過場不畫，那裡原版也是黑的。

| 元素 | 設計 | 資料 |
|---|---|---|
| 底板 | 全寬，深藍到近黑的垂直漸層，上緣一條 1 像素的半透明亮線 | |
| 玩家標籤 | `1P`、`2P` 圓角小標籤。1P 在左，2P 在右並鏡射排列，沒有第二位玩家就不畫 | `HudStatus.active` |
| 血條 | 8 格，對應原版每次命中右移一位的 8 個位元。滿血青綠漸層，剩 3 格琥珀，剩 1 格紅色並每秒呼吸一次。掉格時那一格 200 毫秒淡出 | `hp` |
| 武器 | 28 像素圖示，用既有 `MY` 第 42 到 45 項的 HD 道具球（L、B、K、S）。沒有武器時畫灰色空槽 | `weapon` |
| 砲座 | 兩個小燈，亮的是已裝上的砲座 | `pods` |
| 充能條 | 只有波動砲選項開著時才顯示，放在中央。三級門檻有刻度 | 規格 005「射擊」 |
| 幀計數 | F2 開著時畫在中央偏右，等寬數字 | 原版的幀計數 |

標記：改變規則的選項開著時，HUD 右端畫一個小標籤「強化」，無敵開著時畫「無敵」。

### 工具列與設定畫面的風格

| 項目 | 規則 |
|---|---|
| 形狀 | 圓角 6 到 8 像素，邊緣反鋸齒。按鈕與欄位有 1 像素的半透明邊線 |
| 色彩 | 深藍底（`#0E1422`），表面（`#1B2740`），主色（`#4F9CFF`），文字（`#EDF3FF`），次要文字（`#8FA3C2`），警示（`#FFB454`），開啟（`#5CF2C2`） |
| 開關 | 布林選項畫成滑動開關，不是「開」「關」文字。多值選項畫成分段按鈕 |
| 狀態 | 滑鼠移過時變亮，按下時變深，鍵盤焦點畫主色外框 |
| 圖示 | 工具列按鈕前面有簡單圖示（暫停兩條線、三角形、齒輪、手把、全螢幕四角），用程式畫，不用圖檔 |
| 設定畫面 | 遊戲畫面調暗 60% 留在後面，面板置中，有陰影。分組用卡片，不用線 |
| 載入畫面 | 中文字樣與圓角進度條，第一次啟動解資料與 HD 預載都用它 |
| 動畫 | 面板開關 120 毫秒淡入，不影響模擬時間 |

繪製都在 RGBA 緩衝區做，不依賴 SDL 子系統，版面可以單元測試。

### 打擊回饋

打擊回饋選項從這批開始實作，預設開，只在 HD 模式生效。HUD 與光暈是現代介面，EGA 不量化到 16 色；CGA、MGA 轉成灰階，遊戲畫面維持黑白。

| 事件 | 回饋 |
|---|---|
| 大爆炸、玩家死亡、頭目爆炸 | 畫面震動 180 毫秒，振幅 6 HD 像素，只改輸出位置，不改遊戲畫面內容 |
| 玩家子彈命中 | 命中點一個 80 毫秒的加亮光暈 |
| 開火、爆炸 | 在原版的音訊上疊一層短促的音效（雜訊包絡加低頻），音量低於音樂 |

事件從繪製命令判斷（特效池新世代的圖號），不改核心。

## 驗收

| 編號 | 項目 | 通過條件 |
|---|---|---|
| E1 | 原版模式 | 全部選項為預設時，`tools/rust.sh verify` 全過。改變規則的選項全關時每步雜湊和原版收據相同 |
| E2 | 決定性 | 每個選項開啟時，同一份輸入跑兩次雜湊相同 |
| E3 | 開關有效 | 每個選項有單元測試，證明開啟後行為確實改變，關閉後回到原狀 |
| E4 | 戰場大小 | 120%、150% 從第一關玩到片尾不當掉，敵人從新右緣進場，玩家到得了新邊界 |
| E5 | 設定畫面 | 重綁、衝突、還原預設、指派、拔除都有單元測試。不把設定畫面的按鍵送進遊戲 |
| E6 | 字型 | 介面上的每個字都有點陣，有測試掃過全部字串 |
| E7 | HD 介面 | 原貌模式補間關閉時畫面和 `VgaSink` 逐像素相同。HUD、選單、打擊回饋開關都不改每步雜湊（A6）。血條格數與血量對應有單元測試 |

手感、打擊回饋的強度與 AI 的難度沒有真人驗證時要寫明。
