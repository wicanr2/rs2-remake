# 004 完整版：重寫、顯示模式與四平台交付

狀態：DRAFT（2026-11-05）

## 目標

使用者 2026-11-05 指定：

- 遊戲本體要完整重寫，程式碼要有意義，體感要更好。
- CGA、MGA 要做，在重製內可以切換顯示模式，也要有 HD。
- 完整版要有 Linux（AppImage）、Windows（Zip）、macOS、Android。只出完整版：內含原版資料與 HD，只留本機，不上傳。
- GitHub 的 README 要有截圖。

## 現況與落差

遊戲沒有模擬 x86，也不含 dosgolem。dosgolem 只用來量原版行為，不進遊戲。

`rs2-core` 也還不算重寫，它是照機器碼逐函式翻成 Rust：

| 量測（`crates/rs2-core/src`） | 數量 |
|---|---|
| 程式行數 | 10,742 |
| 以原版位址命名的函式（`s11556` 這類） | 451 |
| 對暫存器欄位的存取（`self.r.`） | 2,503 |
| 對 64 KB 平坦資料段的存取（`self.ds.`） | 2,223 |
| 寫死的原版位址（`a(0x...)`） | 1,982 |

啟動時還會把 `S.EXE` 解包後的資料段整段載入記憶體，表格都從那裡讀。[AGENTS.md](../../AGENTS.md) 規定模擬器的位址與快照不能成為 remake 的資料模型，平坦資料段違反這條的精神。

## 重寫的完成條件

| 項目 | 條件 |
|---|---|
| 資料模型 | 用有型別的 `Player`、`Enemy`、`Bullet`、`Effect`、`Stage`、`TitleFlow` 等描述遊戲。沒有 `Dseg`、暫存器欄位、位址命名 |
| 表格 | 時間表、樣板、移動腳本、調色盤由 `S.EXE` 解析成有名字的結構，雜湊不符就拒絕。解析完不留原始記憶體 |
| 程序 | 依功能切模組，讀程式就看得懂在做什麼。文件註解保留原版位址當證據 |
| 行為 | 同一份輸入，等待長度、幀計數、四個平面、DAC、顯示起點、音訊事件都和原版收據相同 |
| 收尾 | 遊戲裡沒有原版位移。`rs2-core` 改名 `rs2-game` |

## 重寫的方法

一塊一塊改，每一步全部收據都要通過，不從空白重來。空白重來會有很長一段時間沒有任何對拍能跑，也就抓不到錯。

每個領域（特效、敵彈、玩家彈、敵人、玩家、各關、標題）依序做三件事：

1. 函式改成有意義的名字，文件註解保留原版位址當證據。
2. 狀態從 `Dseg` 搬到有型別的結構，暫存器傳遞改成參數與回傳值。
3. 寫 `Mirror`：結構和原版位移之間的 `load`（從傾印或 poke 讀入）與 `store`（寫回給對拍比較）。

`Mirror` 讓資料段比對在整個過程維持逐位元組嚴格。全部搬完之後 `Dseg` 從遊戲移除，`Mirror` 搬到 `rs2-trace`，原版位移只存在測試裡。

- 只在函式內先寫後讀的工作變數，搬完就不存在了，列進 `DS_EXEMPT` 並寫明讀寫它的函式。這類變數如果其實有影響，畫面與其他狀態會在對拍裡分歧。
- 原版靠表外讀寫才成立的行為（敵彈槽進位、裝甲格誤寫、`word_2687E` 殘值等）要逐項寫成明確的程式，對照原版的修正旗標保留。這是重寫最大的風險。
- 全部做完前，每個領域完成就提交一次。

範本是特效領域：`crates/rs2-core/src/fx.rs`（邏輯，沒有原版位移也沒有暫存器）與 `crates/rs2-core/src/mirror.rs`（`Mirror`、共用資料段的具名存取）。每個領域照下面的順序做：

1. 盤點變數，分四類：池陣列、跨呼叫殘值、函式內工作變數、別的領域擁有的共用變數。查法是 `tools/q.sh refs` 加上 `tools/q.sh grep` 找 `[bx+位移]` 這種形式。
2. 分不出是殘值還是工作變數時，先當狀態搬進結構，再做變異測試：拿掉一行賦值或 `store`，收據分歧就是狀態。
3. 呼叫端寫、領域讀的參數變數改成函式參數。列進 `DS_EXEMPT`，也列進 `crates/rs2-trace/tests/fuzz.rs` 的 `DS_EXTRA_EXEMPT`，兩邊各有一份。
4. 共用資料段變數經 `mirror.rs` 的具名存取函式。同一個查表或位址公式只留一份。
5. 暫存器殘值要逐一查過呼叫端才能丟掉。查證結果寫進領域的進度筆記。
6. 繪製命令的欄位有變動時，確認 `rs2-gfx` 的 `sink.rs`、`speaker.rs`、`layer/*` 不讀那些欄位。
7. `Core` 內非原版的欄位（`g2_slots`、`pb_spawned`、`gens`、修正旗標）留在 `Core`，不進 `Mirror`。

每個領域完成的條件：該領域的檔案沒有 `a(0x`、`self.r.`，函式不再以位址命名；`tools/rust.sh verify` 全過；至少一個變異測試證明新加的 `Mirror` 欄位真的有被比對。

## 體感

原版每秒只更新 9.1 次，按鍵到畫面反應要等 110 到 220 毫秒。規則不改，難度與對拍都不受影響，改的是輸入與顯示：

| 項目 | 做法 | 驗收 |
|---|---|---|
| 玩家機零延遲 | 依目前按鍵在顯示層預測玩家機位置，下一個邏輯步校正 | 按鍵後下一次繪製玩家機就動，模擬雜湊不變 |
| 短按不漏 | 兩個邏輯步之間按下又放開的鍵，至少維持到下一個邏輯步 | 單元測試 |
| 手把 | SDL GameController，桌面與 Android 都支援 | 對應表單元測試 |
| 原版手感 | 工具列可切回原版時序，預測關閉 | 雜湊相同 |

這些都不碰模擬，所以 `--original-bugs` 的收據比對不受影響。實際手感沒有真人驗證時要寫明。

改變規則的強化、工具列與手把設定畫面在 [規格 005](005-enhanced-mode.md)。

## 顯示模式

- `DisplayMode`：VGA、EGA、CGA、MGA。工具列與快捷鍵切換，切換不影響模擬。
- 先盤點 101 個 `byte_1CF74` 判斷點，分出只影響繪製的與影響邏輯的。影響邏輯的要另外決定如何不影響切換。
- 原版對拍：`rs2dyn` 要補 CGA 模式 6 與 Hercules 的畫面記錄。
- HD：先用 `workspace/hd/assets/mono/` 的 1,526 張推導結果，看實際畫面後由使用者決定要不要重畫。

## 交付

| 平台 | 產物 | 工具鏈（本機既有） | 驗證 |
|---|---|---|---|
| Linux x86_64 | AppImage | `dosgolem-rust-cross`、`fd2-build-appimage` | 解開後在乾淨容器跑，Xvfb 截圖 |
| Windows x86_64 | Zip | `dosgolem-rust-cross`（mingw、`/opt/sdl2/windows`） | Wine 跑實際產物 |
| macOS | universal `.app` 的 Zip | `dosgolem-rust-cross`（osxcross、SDK 15.5） | `lipo`、Mach-O 靜態檢查。沒有 Mac，不能宣稱實機驗過 |
| Android | APK | NDK 27.2（`rich2-go-android`），另裝 Rust 的 Android 目標，SDL 的 `android-project` 在 `sdl2-sys` 內 | `rich2-android-emulator` 跑實際產物 |

- 依 `rulebook/82`，驗的是打包後的產物，不是開發機的二進位檔。
- 每個包都帶 `LICENSE`。APK 看不到檔案，要在遊戲內的關於頁顯示（`rulebook/85`）。
- Android 是移植：要有觸控按鈕、生命週期、可寫目錄，先出設計稿再實作。
